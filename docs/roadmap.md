## 1. 产品目标与生产范围

**面向开发者的本地知识库：把代码、项目资料和人工结论连接为有适用范围、有证据、可维护的知识，供人和不同 Code Agent 共用。** Java 多仓是首批结构化解析对象，独立文档文件夹和已有 Markdown/Obsidian vault 同样可以独立接入。

核心使用路径：登记来源 → 搜索与阅读证据 → 分清需求/实现/观察/决策/推断 → 保存与修订结论 → 新会话复用 → 依据变化后复核。

生产级意味着明确支持范围内的正确性、持久性、恢复、安全、可诊断性、安装和升级均有验收。支持范围写进每个发布版本，不能用“原型能跑”替代。

| 维度 | 首个生产版本的完整范围 | 后续扩展边界 |
|---|---|---|
| 部署 | 本机、单个知识所有者；允许多个 Agent 会话与人工页面并发；本地磁盘 | 团队共享服务另立认证、授权、审计与服务部署方案；不直接共享数据库文件 |
| 来源 | 一个或多个代码仓、独立文档目录、Markdown vault；无 Git 也能用 | 远端业务系统、网页抓取、运行时观测分别建立连接器与数据策略 |
| 格式 | MD/TXT 核心；Java/SQL/XML/前端调用的已声明子集；PDF/DOCX 可选能力有独立验收 | 扫描 PDF/OCR、音视频和其他语言按样本扩展，不伪装为已解析 |
| 入口 | CLI、MCP、本地搜索与知识维护页面；Claude/Codex/ZCode/DSH 四客户端分别验收 | 不要求依赖 Obsidian 或某家模型；不建设通用 Agent 运行时 |
| 网络 | 核心查询、保存、复核离线可用；本地 UI 仅回环监听 | 模型/嵌入或远程来源显式启用，并说明发送范围 |
| 支持平台 | 目标 macOS/Linux/Windows；候选 Python 3.11–3.14，以核心/各 extra 的实测矩阵发布 | 当前源码仍写 >=3.9；调整版本要求须随实现与迁移说明提交，不能由计划冒充兼容证据 |

这是首发部署边界，不把“生产”缩成只支持单进程或只跑样例。团队能力保留为下一阶段产品分支；只有明确需要共享时才改变首发架构。

## 2. 从四个项目吸收什么

以下仓库沿用前轮已明确的比较对象。本轮读取官方资料和仓库元数据，未安装或复现它们的效果；固定参考提交见审计 JSON。

| 参考 | 吸收的能力 | domimap 的实施决策 |
|---|---|---|
| [claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) | 用户持有资料、带出处的陈述、保存与维护流程 | 独立人工知识层、可恢复写入、普通 Markdown 交换格式 |
| [Codebase-Memory-MCP](https://github.com/DeusData/codebase-memory-mcp) | 持久结构图、AST/语义能力与 MCP | 解析适配接口、精确身份/位置、显式未解析关系；只评测并选一条主解析路径 |
| [CodeGraph](https://github.com/colbymchenry/codegraph) | 返回可读源码、跨会话复用、索引新鲜度 | 证据包与按 ID 阅读、变更可见、可恢复更新 |
| [Graphify](https://github.com/Graphify-Labs/graphify) | 异构资料、关系依据、导航与导出 | 统一证据边界、局部关系视图、资料适配器 |

它们是设计参照，不是同时安装的四个必需后端，也不是 domimap 已有的功能。上游语言数量、星数、token/延迟宣传不成为本项目指标。MIT/Apache 等元数据仅用于后续来源清单，正式复用代码、提示词、图标或分发二进制时检查对应版本文件与通知要求。

## 3. 当前基线与要保留的资产

- v0.4.0 有约 1,330 行 Python 核心；多仓扫描、Java 框架规则、中文检索、领域导航、CLI/MCP 和夹具值得保留。
- 生产准备度审计时原型测试 22 项，文件整理后增加维护验证；最新数量由 `make verify` 实测。原始回放 Top-5 仍为 6/8，旧 8/8 混入场景卡兜底，不作为生产或竞争质量证明。
- 同名实体合并、证据定位不足、构建恢复、MCP 入参/容错、扫描边界仍有缺陷。新诊断复现：图丢失仍 no-op、非法 JSON 类型令服务退出、文件链接越界摄入。
- 没有人工知识持久层、完整手动界面、上下文加载、时间排序或四客户端联调记录。目录未建立 Git；缺 LICENSE/贡献/安全/发布说明及 CI。已有清理工具、临时测试输出和忽略规则；它们不等于产品数据生命周期已实现。
- 本机仅验证 macOS/Python 3.14.4 的现有测试。未构建新分发物，未做 Windows/Linux、新客户端或真实业务效果验收。

因此当前状态是**可运行原型**。后续逐模块迁移和保持可运行切片，不先整体重写，也不保留错误语义来维持旧测试绿灯。

## 4. 架构决策与对旧计划的实质调整

| 决策 | 原因与边界 | 时机 |
|---|---|---|
| 公共应用服务供 CLI/MCP/UI 调用 | 三入口共享筛选、时间、证据、保存与错误语义，避免三套实现 | M1 定契约，M2 接线 |
| SQLite 事务元数据/人工知识提前 | 幂等保存、冲突检测、审定、并发和发布指针是持久性需求；不再只等性能瓶颈 | M1 建最小骨架，M3 完成人工层 |
| 派生图/索引按不可变 generation 发布 | 元数据与图不混代；发布前校验，失败继续读上一完整代 | M1 |
| 图导出 JSON 保留；FTS/向量独立决策 | SQLite 元数据不等于立即把全部遍历迁入 SQL；FTS5 有能力检测和中文回退；向量按失败集验证 | M2 基线，增强按证据 |
| MCP 优先固定官方 SDK 的受支持版本 | 核心 stdlib 低依赖保留；MCP 是明确 extra，避免手工协议长期追版本 | M0 兼容试验，M2 迁移 |
| 原文证据先于可引用 ID；知识按陈述复核 | 无 Git/源删除仍能解释历史；需求不被当作实现，复核不整篇串用 | M1/M3 |
| GitHub 工程底线前移 | 来源/测试/包/许可证从实施开始可追溯；公开预览与正式生产发布分开 | M0 起，M5 正式发布 |
| 真实任务从首切片开始 | 第一次反馈不再等到最后一个工作包；不以扩图规模代替价值 | M2 起 |

SQLite 方案针对设备本地、短事务和有界写并发，符合其[官方适用边界](https://www.sqlite.org/whentouse.html)。多客户端要排队写入；数据库禁止放在多人同时访问的网络盘。M1 验证本机文件系统与驱动支持后记录具体日志/同步配置。完整发布协议见架构文档。

## 6. 实施顺序与每阶段出口

依赖：**M0 → M1 → M2 → M3 → M5**；M4 在 M2 后并行推进，与 M3 一起汇入 M5。这里的并行是工作依赖设计，不要求额外 Agent。M0 的安全/测试底线和 M2 的试用贯穿后续阶段。

每阶段再拆为四个小切片，详见[逐步执行单](implementation/step-by-step.md)。不一次合并解析器、全部存储和完整 UI；每片先写 spec/反例，再实现和收敛。22 项需求、49 个案例及实际状态分别维护于 specs/requirements、acceptance、progress JSON，不重复创建另一份“已完成”清单。

### M0：工程基线、来源清单与可执行约束

- [ ] 建立 Git 与源码/用户知识/生成物分离规则；整理现有本地生成目录，不删除或提交用户资料。提供合成样例，完善 ignore 与分发 allowlist。
- [ ] 核对既有 MIT 意向及素材/代码来源，补 LICENSE、第三方清单、CONTRIBUTING、SECURITY、CHANGELOG 与发布状态约定；作者归属不凭空填写。
- [ ] 建 CI 基线：核心测试、正确语义反例、包构建/干净安装、文档链接、extras 检查。测试各自建临时输入/输出，不能依赖运行顺序或上次产物；修回放混合统计，独立保留 raw/scenario，仿造不存在 ID 不得通过评分。
- [ ] 用样例确定 MCP SDK/客户端兼容接口；登记四客户端实际产品与版本。版本矩阵未验证时保持空缺。
- [ ] 固定配置/结果/错误/版本的最小 schema、威胁边界、公开数据集与测量方式；接口文档标 planned。
- [ ] 使用已提供的规格/任务/证据检查器，建立首个真实任务和 Git diff 范围检查；准备四竞品健康检查、dev/确认隔离及公共输出映射，先小样例验证比较可行性。

**出口**：从干净 checkout 可以重复跑原型与失败诊断；当前失败列为未完成任务，不得把绿灯误作生产验收。后续修复合入的契约回归必须阻止同类缺陷复发。此时可准备公开开发仓，但发布前还要通过第 9 节公共工件门槛。

### M1：可信身份、来源、证据与构建事务

- [ ] 落地 R01–R03：显式 workspace/repo/module/source ID，关系端点与证据一致；无部署映射不推定线上版本。默认知识库由配置选择，不暗用 mini。
- [ ] 正确性最小夹具先失败：跨仓同 FQN/同 basename、重载、嵌套/空方法、字段别名、同路径文档、无 DDL Mapper、同名表/Topic 隔离。
- [ ] 有限解析试验：lite 基线、直接 Java AST、一个已通过接口/许可证筛选的现成后端；固定版本、同输入测 owner/span/signature/调用解析及部署成本。选择一条路径，复杂派发未知可见，不默认绑定 Graphify。
- [ ] 建 SQLite 迁移/事务骨架与 generation 发布；捕获的字节同时用于哈希、解析和片段，不将路径/mtime 当内容版本。配置、种子、解析器版本进入失效依赖。
- [ ] 根目录与符号链接边界、目录排除、大小/解析时间上限、失败/跳过/截断清单。固化首次返回的证据，引用前可读取；无 Git 修改/删除后不冒充旧原文。
- [ ] 覆盖发布前后中断、两写者竞争、磁盘满、坏缓存、图丢失、删除/移动与扫描中变更；不完整构建保留上一完整代并显示状态。

**出口**：规范化对象/关系/证据不串范围；坏产物可恢复；手动更新与全量构建等价。人工知识存储尚未完成时只提供兼容契约，不能宣称已经保存复用。

### M2：人和 Agent 共用的证据检索切片

- [ ] 公共 Query/Read/Trace/Context 服务；代码与 MD/TXT 分别召回，精确匹配/片段检索、显式引用、来源家族折叠。来源范围与有效性先于时间降权。
- [ ] 结果对象含 snapshot、适用范围、证据 locator/摘录、来源状态/时间依据、推断与缺口；完整引用按条目预算。支持 partial/unchecked/unavailable，禁止把“没查到”说成“不存在”。
- [ ] 图只按问题需要扩展；限制节点/边/深度/耗时。影响方向按关系定义，MENTIONS/领域归属不冒充因果；路径强度不高于最弱边。
- [ ] F2：CLI 结构化输出、本地只读搜索与证据阅读；打包静态资源，无模型可用。F3：可信上下文加载、模板、来源/预算诊断；普通摄入规则文件不升级为指令。
- [ ] F4：冻结 as_of 实现可解释时间策略；长期有效/日期未知/未来/替代/过期/历史范围各有样例。保留补充计划中的候选公式，参数须校准。
- [ ] F1 先在一个实际客户端走通全链，再独立完成另一个可运行客户端；配置预览、幂等合并与受管撤销，不破坏用户设置。接口层不等待四端全部完成才交给 M3。
- [ ] 固定首批 10 个真实任务，包含版本差异、PRD/代码冲突、重复和无证据；先发现问题，再扩大独立验收集。不得把演示夹具当真实任务。
- [ ] 在 dev 数据上比较五系统和文本/图/人工知识消融，分层定位差距；确认 gold 留在独立环境，不读取它反复调参。

**出口**：人能搜索并打开依据；新会话 Agent 能发现工具并按证据回答；同请求三入口共享语义。技术预览可在此发布，但成熟度、未完成功能和客户端逐项状态必须清楚。

### M3：可持续积累的知识闭环

- [ ] R05：单条知识提交，内含轻量 claims；需求/实现/观察/决策/推断类型，各自支持/反对证据、范围与状态。自由笔记允许保存，不整篇自动标 verified。
- [ ] SQLite 短事务实现 expected_revision、idempotency_key、历史修订和审定事件；同键同内容返回原结果，同键不同内容冲突；超时后可查提交结果。查询不默写，明确保存命令不重复询问。
- [ ] R06：source/配置/推断规则到 claim 的依赖、变化摘要和待复核队列；确认需绑定当前证据和范围，点击/重建不刷新复核。推断被接受也不改成 EXTRACTED。
- [ ] R07：独立导出/恢复、Markdown/Obsidian 展示与显式导入；正文带稳定 ID/修订，外部编辑冲突可预览，不能将导出目录回灌为新独立证据。
- [ ] 引用证据固定保留；临时证据有公开 TTL、配额与过期状态。删除/遗忘清理受管视图及约定的保留物，外部客户端历史不作全量删除承诺。
- [ ] 本地页面补保存、修订、复核和失效处理；无 AI/模型也能完成。MCP 写能力明确启用、与只读分开，服务端校验参数和目标范围。

**出口**：至少 10 条知识完成保存→修改/审定→新会话再检索→依据改变后复核；并发/重复/中断不丢已确认写入。空目录恢复保留正文、修订、范围、审定与引用。重建机器图不覆盖人工内容。

### M4：完整接入、覆盖边界与运行加固

- [ ] F1-C1–C4 分别完成版本/平台/transport/新会话/读取/指令生效/撤销记录；路径含空格、换目录启动、包升级与知识库移动可诊断。
- [ ] PDF/DOCX extras 区分未安装、损坏、加密、无文本、解析失败和截断；页码/段落定位与摘录可复核。大文件/压缩容器受资源限制；不承诺 OCR。
- [ ] Java 框架能力矩阵：Spring 路由、MyBatis 动态片段、RPC 多 provider、MQ 集群/角色、JPA、前端 HTTP 方法与路由范围逐项声明支持/部分/未知；不以静态分析承诺运行时根因。
- [ ] 在正确手动更新上实现仓记录复用；监听作为可选模式，启用时合并事件、检测漏事件/溢出/分支切换并全量校验。无法核实时显式 stale；未启用监听不宣称实时。
- [ ] R08/R10：多进程读写与锁超时、查询取消、缓存并发、网络/UI 边界、日志隐私、备份、升级失败回退与数据迁移；从 M0 起已加固的规则在全部入口统一。
- [ ] 压力与长运行验证；对实际支持平台/extras 测安装及闭环。不存在的环境保持待验收，不用本机导入成功代替。

**出口**：四项明确需求完整验收；运行和格式能力无隐含模拟。M4 与 M3 的结果共同进入 RC，而非靠安装说明宣布生产完成。

### M5：独立验收、RC 与生产发布

- [ ] 执行第 7 节全部硬门槛与质量/资源验收；未解决的身份串接、证据伪装、数据丢失、越界、协议崩溃阻塞发布。
- [ ] 受支持版本迁移、备份与空目录恢复、同目录多会话、升级包和卸载保留用户知识的演练。
- [ ] 生成 README 中英快速开始、客户端/格式/平台矩阵、架构/贡献/安全/迁移/备份说明、示例、变更日志、性能与质量报告。
- [ ] 从净化源码构建 sdist/wheel，干净环境安装并跑 CLI/MCP/UI/知识闭环；检查包清单、许可证、依赖/哈希，GitHub 工件与被验收内容一致。
- [ ] 执行四竞品真实确认比较，Hit@5、任务 Accuracy、事实 micro-F1 对每个竞品都严格更高且修正下界 >0；打平、缺运行和样本不足不能通过。
- [ ] RC 修复只重跑受影响与必需检查；没有新变更或新风险不重复扩大测试。所有要求有记录后才标正式生产版本。

**出口**：R01–R14 和 F1–F4 均有当前版本直接证据，`make release-check` 通过。样本、环境或客户端缺失时保留待验收，可以继续预览，不能把本计划完整目标标完成。

### 完成首发后按条件扩展

更多语言、语义向量、自动知识综合、全文近似去重、全图可视化、社区发现、运行时关联和团队共享分别立项。触发条件来自失败样例、工作量或测量；自动生成保持草稿与依据。团队版新增身份认证、资源级 ACL、隔离、集中备份、审计和服务 SLO，不靠把本地 UI 绑定外网实现。

## 7. 验收门槛与性能预算

### 7.1 不允许被平均分掩盖的硬门槛

1. 受支持构造的身份/来源/范围不串接；不能把未知、需求或引用存在等同于结论已证实。
2. 返回的证据 ID 对应完整版本片段；到期/删除/不可用明确表示，绝不用当前文件冒充历史。
3. 任意发布中断不暴露混代产物；确认提交的人工写入在承诺的本地文件系统/过程故障模型下 RPO=0。硬盘永久损坏依赖备份，不作零损失承诺。
4. 非法请求返回有界错误，后续有效请求仍可用；入参数值/消息大小/遍历/解析预算可执行。
5. 来源与引用读取不越过登记根；普通文档不变成指令；UI 不执行资料脚本或接受非受权写入。
6. 重建、升级、导出/恢复不丢人工知识；冲突显式，删除满足受管范围约定。

这些不是“证明永无缺陷”的绝对保证，而是必须有故障/反例测试且已知违反项为零的发布要求。发现违反时修复或撤回相应支持声明，不能只调总分。

### 7.2 独立质量与任务验收

- 原 20 需求/10 故障/20 负例仅作早期试点；正式比较至少 300 可回答、100 不可直接回答、20 独立项目族 cluster 和五个种子，四类可回答任务各至少 50。开发/确认按来源族隔离，真实材料授权不足时保持未完成。
- raw hit@5、scenario hit@5、MRR、证据支撑、范围正确与最终任务成功分开计；扩展节点/第 6–10 候选不补 Top-5 分。
- 原试点目标 16/20、7/10、19/20 只用于开发观察；正式比较要求 Hit@5 ≥80%、任务 Accuracy ≥85%、事实 micro-F1 ≥85%、负例正确处理 ≥99%，并对四竞品三指标全部严格胜出。领域导航适用时抽最多 100 服务，目标 ≥90%，未知计入分母并报告覆盖。
- PRD 写乐观锁但 SQL 未比较旧版本、跨版本同名、复制资料、近期草稿/旧有效规范、源删除/缺解析均进入困难样本。伪造 ID、错源引用和不支持结论不能通过评分。
- 支撑度检查按预先标注的必要陈述与源位置；所有评估中已知的错误确定说法必须修正/降级，不能以 ≥80% 搜索命中容忍伪证据。
- 同任务/预算比较手动关键词与读文件、仅文本、图加文本、再加人工知识；记录首次可核验依据时间、工具调用/返回量/实际可得 token、复用节省与复核误报成本，不承诺未经测量的倍数。

精确定义与完整流程唯一以[比较规格](../specs/benchmark.md)为准：三指标分别计算，12 个成对差值的 Bonferroni 修正单侧下界均 >0。原生检索诊断不与端到端任务混算。未安装竞品不是零分；若竞品满分导致无法严格超过，目标仍未达成，不能静默改验收。

### 7.3 性能与恢复：先固定输入，再校准阈值

以下是**候选工程预算，尚未测试或承诺**。M2 固定数据集、硬件、查询集、冷/热定义及阈值并记录；RC 不得根据失败结果悄悄放宽。若支持规模变化，必须公开变更适用边界和理由。

参考配置：8 逻辑核、16GB 内存、本地 SSD；冻结输入清单约 10 仓/10,000 源文件/1,000 文档，另加 10,000 人工知识。文件量/字节/分布明确记录，输出节点数只作观察，不作可操纵的输入规模。

| 指标 | 候选预算 | 验证方式 |
|---|---|---|
| 热检索 p95 / 冷启动加首查询 p95 | ≤500ms / ≤3s | 同范围/预算，缓存状态与样本量公开 |
| 有界关系查询 p95 | ≤2s | 包含高出度和未解析路径，超限返回 partial |
| 全量 / 单仓 100 文件变化更新 | ≤5 分钟 / ≤30 秒 | 输入清单固定，同时检查正确性与等价 |
| 峰值常驻内存 | ≤2GB | 构建/查询分报；记录各进程合计与额外解析器 |
| 同机并发 | 4 个客户端、合计 8 个在途读取 + 串行保存/构建发布 | 无混代/丢写，队列与超时有界，延迟另报 |
| 长运行 | 至少 24h 固定混合负载 | 内存/磁盘增长、错误、锁与队列；非只挂空进程 |
| 恢复 | 10,000 条知识在候选 10 分钟内恢复可查 | 备份来自受支持在线备份流程，校验正文/历史/引用 |

热查询性能不能通过删掉完整引用、减小必要范围或返回错误候选达标。备份 RPO 取决于用户选择的频率；在诊断中显示最近成功备份与可恢复范围，不无条件承诺 24h。

## 8. 第一批可合并工作与旧工作包映射

先实施小的可审查变更，每次附反例、迁移影响和验收结果。建议第一批顺序：

1. 工程基线：Git/ignore/许可证来源/干净测试输出/真实回放评分/构建安装 CI。公开仓状态仍为原型。
2. 契约与解析实验：workspace/source/entity/evidence 完整例子，错误碰撞夹具和固定版本对比记录。
3. 可信构建：身份接线、SQLite 元数据骨架、固化证据、generation 发布、故障恢复与范围防护。
4. 查询垂直切片：公共结果→CLI/SDK MCP→按 ID 阅读→本地搜索页；随即开始真实任务。
5. 上下文与时间策略、第一条真实客户端体验；再衔接知识保存和其余客户端。

不在同一个变更里完成解析器替换、全部存储重构和完整 UI。先建立契约与失败证据，正确迁移既有规则。

| 旧工作包 | 新落点与调整 |
|---|---|
| WP1 身份/解析边界 | M1，工程基线 M0 先行；补适用范围、来源家族、陈述兼容字段 |
| WP2 构建恢复 | M1；事务存储与发布协议提前明确，基础安全同步 |
| WP3 检索/入口 | M2 与 M4；核心/页面/四客户端分开验收，时间/上下文保留 |
| WP4 人工知识 | M3；按陈述复核、备份/恢复/交换格式纳入完成门槛 |
| WP5 规模增强 | 必需资源限制/增量恢复进 M4/M5；向量/更多语言仍按证据启动 |
| WP6 体验/发布 | 工程/开源底线进 M0，试用进 M2；完整发布与升级证据进 M5 |

## 9. GitHub 与版本发布策略

公开源码可以早于生产版，但必须先审查**实际待上传集合**：

- 包含产品源码、合成夹具、计划/文档、构建与测试；排除真实仓库正文/路径映射、用户笔记、查询日志、凭证、证据快照、生成图/缓存和本机环境。
- 不仅检查 Git 工作区，也检查已跟踪历史、sdist/wheel、截图/演示、CI 工件与 release 附件；原始本地审计发布前需净化路径与输出。
- LICENSE、第三方来源与分发清单齐全；元数据与实际成熟度一致。项目首页 URL 不作为仓库已创建/已发布证据。
- CI 对受支持 Python/系统与 extras 做有界矩阵，锁定构建/测试环境；发布凭据只给发布任务，PR 不获得秘密或发布权限。Actions 固定依赖/提交，依照 [GitHub 安全使用参考](https://docs.github.com/en/actions/reference/security/secure-use)。
- 分发同时检查源码包和 wheel 的资源/种子/页面/许可证；从另一目录启动，读写用户数据目录；不能只在源码目录导入成功。

候选版本含义：`0.5.0aN` 表示可信检索预览，`0.6.0bN` 表示知识闭环可试用，`1.0.0rcN` 表示完整功能等待发布验收；版本名不代替门槛。现有 v0.4.0 不重命名冒充新能力。

正式 tag/release 对应不可变源码提交，附支持矩阵、变更/迁移/回退说明、数据格式版本、依赖清单、SHA-256 与可获取的构建来源证明。包发布后用发布工件重新跑安装 smoke；失败撤回/修复发布，数据格式有变化时明确风险和恢复路径。

本轮不创建远端仓库、不上传文件、不发布包。准备工作在 M0 开始；上传时以当时实际文件和授权为准，不延后到最后才第一次清理。
