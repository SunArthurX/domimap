## 产品定位与第一条用户路径

**本地研发知识库，以 Java 多仓工作区为第一个切入点。** 可保留并复用源码依据、项目资料、业务解释与架构决策，后续按真实需要扩展语言和资料。

首个主场景：

> 输入一条需求 → 找到实现与文档证据 → 看清已知和缺口 → 保存有出处的结论 → 补充人工判断 → 新会话复用 → 来源改变后重新核对。

领域地图先作为导航；故障调查先提供静态线索。三者不再同时作为首版本的同等建设主线。这个优先级仍是产品假设，首个可用切片就开始观察真实任务，再据反馈调整。

四个参考项目分别提供知识治理、代码结构、可读上下文与新鲜度、异构资料连接的设计经验；正式选型不以“集成四家”为完成条件。上游核查链接与观察边界见[首轮分析](../reviews/2026-10-16-direction-review.md)。核心保留低依赖运行路径，解析、文档与模型能力通过明确的可选适配器增强；缺少适配器时如实降级。

## 交付顺序与依赖

| 阶段 | 工作包 | 交付物与完成门槛 |
|---|---|---|
| v0.5 A：可信数据切片 | WP1 身份/解析边界 → WP2 构建恢复 | 同名对象分开；来源可定位；失败构建不会被当作最新 |
| v0.5 B：可读证据切片 | WP3 检索/图查询与使用入口 | 证据包、四客户端接入、人工搜索、轻量上下文与时间策略分别验收 |
| v0.6：积累与复用 | WP4 单条知识保存与生命周期 | 保存、修订、审定、再次检索、失效提醒可用 |
| v0.7：精度与规模 | WP5 条件触发的增强 | 按真实失败样例补解析；按测量改善存储、增量与监听 |
| v0.8：体验与发布 | WP6 真实任务与产品收尾 | 本地界面、支持平台与发布验证；业务效果单独验收 |

依赖主链：**WP1 → WP2 → WP3 公共检索核心 → WP4**。小型解析器验证在 WP1，全面集成按需要推进。四客户端适配与只读页面分别验收，不阻塞知识保存核心，但不能以公共 MCP/CLI 可用冒充四客户端接入已完成。WP5 不是知识保存的前置条件；WP6 的试用观察从 WP3 开始。

不预设“10 周完成”、16 万节点的统一延迟指标或所有平台同时过线；在首切片与固定试点规模测量后，才设工期和性能预算。

## WP1：来源身份与解析边界（下一工作包）

- [ ] 固定最小失败夹具：跨仓/跨模块同名类、跨类同名方法与重载、同路径文档、空方法串入下一方法调用、字段接收者改名。
- [ ] 定义 repo/module、source、entity、evidence 的最小契约；对照夹具验证候选 ID 和来源，明确未解析对象的表示，不合并不确定符号。
- [ ] 为 AGENTS/SOUL 的可信路径、上下文预算和确定性查询偏好保留配置契约；文档时间记录区分更新时间、采集时间、复核时间及可信度。生成可对外引用的 evidence_id 前固定可展示片段，不依赖 Git 或用户先保存笔记。
- [ ] 完成受限解析验证：当前 lite 作基线，一个 Java AST 方案与一个经接口筛选的现成后端作候选；只验证 owner/span/signature 与上述反例，不先搭全面适配。
- [ ] 选定最小解析路径后，贯通 records → 框架规则 → graph → 查询的身份和证据引用；升级 `domimap.graph.v2`。旧派生图明确重建，人工知识不在清理范围。

边界：此包不要求类型解析全覆盖，不建立完整 RPC/MQ/路由解析器，不迁数据库，也不建设知识编辑界面。

**出口**：同名对象不串仓，来源与对象一致；空方法不出现假的调用；接收者无法解析时显式未知。输入顺序变化不改变规范化身份集合。解析器尚未实测胜出时不能写“已选型”。

具体操作、文件与验收见[WP1 执行单](../../../implementation/source-identity.md)。

## WP2：构建恢复与可信快照

- [ ] 构建分为先登记节点、再解析关系、最后打标；修复无 DDL 时的 SQL 读写漏边与 `root/label` 混用。先允许正确全量重建，不把真正增量缓存作为此包前提。
- [ ] 更新前检查 graph/manifest/必要记录完整性；配置、种子、抽取规则和内容校验策略纳入失效。图缺失、缓存损坏、删除/重命名、配置变化必须能重建，不能误报 no-op。
- [ ] 保存文档时间依据与质量标记；复制、touch 与重新扫描不能伪造新的复核时间。历史证据片段按版本留存，索引重建不清理已被知识或审定固定的快照；未保存的额外历史上下文明确返回不可用。
- [ ] 用同一 generation 发布派生产物；失败保持上一完整快照，重试可恢复。限制同一输出目录的并发写者；扫描中变更要重试或标记未收敛。
- [ ] 登记包含/排除范围，输出与人工知识目录不回灌；realpath 越界的链接不能悄悄读入。coverage 记录读取/解析失败、跳过、截断、缺依赖；不把源正文作为可执行指令。

**出口**：复现本次三个故障后均能恢复：图删除、构建在发布前失败、指纹匹配但缓存结构损坏。删改后的手动更新与同版本全量重建在规范化实体/关系/证据集合上等价。

“已索引快照”与“当前文件已核验”分开表达。多个仓的扫描时间不代表它们拥有同一业务版本；每个来源保留自己的 revision/hash。

## WP3：证据检索与图查询语义

- [ ] 文档先支持 Markdown/TXT 的标题/长度片段，记录范围与内容哈希。代码与文档分别召回后融合；人工知识先定义扩展接口，实际通道在 WP4 的存储契约建立后接入。文档工具不能先取全图 Top-K 再筛文档，领域名不作为功能事实证据。
- [ ] CLI/MCP 共用请求与结果契约，明确 raw/scenario 模式。修 MCP schema 与入参约束；保留预算内完整引用，以证据 ID 获取上下文。截断按证据项执行，不能截掉出处。
- [ ] 按下表限制影响面遍历；未解析、候选、多 provider 或缺数据源的关系不得默取第一个。完整框架适配按实际失败案例进入 WP5，首切片先阻止错误高置信输出。
- [ ] 建严格评测入口，旧 8 条保留为 smoke；命中按独立标注的预期实体/源位置判断。只对返回证据做有界内容核验；未核验范围标 unchecked，避免每次查询遍历全工作区。
- [ ] 提供 Claude/Codex/ZCode/DSH 快速连接与诊断、客户端实际加载的知识库使用指引；新增 AGENTS.md / SOUL.md 模板、上下文解析和只读 `kg_context`，具体命令、边界与逐客户端验收按[四项能力补充](../../../capabilities.md)执行。
- [ ] 保留人工 CLI 搜索，增加 JSON/来源筛选与本地只读搜索页；CLI/MCP/UI 共用文档时间降权、日期依据和过时提示。无 AI 客户端或模型配置时也可手动查询；四客户端和页面独立跟踪进度。

| 关系或场景 | 查询语义 |
|---|---|
| `CALLS` | 查被调用者的潜在影响时反向找调用者；不承诺完整动态派发 |
| `CALLS_SQL` + `READS/WRITES` | 从表反向到 SQL、再到调用方法；关系逐步保留出处 |
| Topic 变更 | 按 `PUBLISHES`/`SUBSCRIBES` 的各自方向检查生产、消费角色，不能统一反向遍历 |
| 路由契约变更 | 检查处理方法与前端引用；同时考虑服务范围、HTTP method 和路径候选 |
| `CONTAINS` / `BELONGS_TO` | 默认用于导航，不直接当作风险传播 |
| `MENTIONS` | 表达资料关联，不证明调用、依赖或因果 |

**出口**：有文档匹配但代码占据前几名时仍能返回文档；只有领域词时不声称功能已被证实；Topic 消费者不漏报、Domain 不冒充调用依赖；来源与未覆盖项清楚。路径置信不得强于其中最弱的一条关系。

最小结果包含：`snapshot_id`、主候选、证据与 locator、抽取/推断依据、`source_status`、时间依据/衰减因子、覆盖缺口。对问题支撑区分“有支撑 / 部分支撑 / 未找到 / 未检查”；候选命中本身不等于完整答案。规则/人设上下文与业务证据分开返回。

## WP4：保存、审定、修订、复用

- [ ] 单条知识记录作为最小提交单元，正文、最小元数据和引用摘录一起保存。定义稳定 note_id、修订与 expected_hash；索引和 Markdown/Obsidian 导出均为派生视图。
- [ ] 分开记录类型（事实/解释/决策）、`review_state`（draft/accepted/withdrawn）和 `evidence_status`（unchanged/changed/missing/unchecked）；保留作者、理由与冲突结论。人工决定可基于作者明确理由，不伪造源码证明。
- [ ] 在此包接入人工知识召回；人工复核的 `last_verified_at` 必须绑定内容版本。补充有效期和被替代关系，默认当前回答不拿明确过期/被替代内容作依据，历史查询仍可查看；年龄降权不自动撤回审定。
- [ ] 保存提供预览与幂等操作；明确保存指令可直接执行，无需反复确认。冲突不覆盖，失败可恢复，旧修订可查看；自动多页合并与编辑用户现有 Obsidian 页面后移。
- [ ] 人工笔记与审定进入检索；机器重建不得覆盖。待审边的接受/拒绝以独立 ReviewEvent 保存，只对仍匹配的证据版本应用，不把接受变成 EXTRACTED。被引用片段保留有限、内容寻址的历史快照，源变化或删除时列出受影响结论，允许保留历史解释并提示复核。

**出口**：至少 10 条知识走通保存→修订/审定→新会话检索；重建不丢知识，重复保存/冲突保存/中断恢复结果可检查。已接受但源变化不等于结论为假，也不能继续无标记当作当前依据。

首版无模型也能手工保存与复用；查询不会默默写知识或替用户接受草稿。先以 CLI/MCP 和可读导出试用，再决定编辑界面。

## WP5：按证据启动增强

- [ ] 解析：根据未解析/错误样例补 Java 类型、接口与框架绑定；固定上游版本并记录部署、接口、来源定位和许可证文件。不同时建设四套后端。
- [ ] 规模：测固定硬件与数据集的构建、冷/热查询 p50/p95、内存及索引大小；确认瓶颈后才迁 SQLite/FTS5，检测 FTS5 可用性并保留中文策略和图导出。
- [ ] 更新：先每仓记录复用，再按需要做文件哈希、依赖失效与监听；覆盖分支切换、漏事件、队列溢出与发布失败。任何优化都保持全量/增量等价。
- [ ] 语义：片段、别名与显式引用不足时，再对照验证向量或模型；领域社区、更多格式和运行时边分别有真实样本后再启动。

**出口**：只对实际启用的能力设置验收，不因未做数据库迁移或未装模型阻塞知识闭环。静态调查与运行时根因判断分开。

## WP6：试用反馈、界面与发布

- [ ] WP3 开始观察需求任务、WP4 开始观察知识复用；记录用户是否查到依据、能否修正、能否再次使用，决定主场景是否需要调整。
- [ ] 在 WP3 只读人工搜索页基础上补知识编辑、审定/失效列表与上下文编辑体验，复用同一查询/保存服务；领域导航与局部图按使用需要补。
- [ ] 对实际声明支持的平台做安装、MCP、资源打包与最小闭环验证；不把“设计兼容”写成已验收。公开发布物只放产品文件和合成样例。
- [ ] 技术预览与业务验收分开：样本不足可交付明确标记的预览；业务效果、保存可靠性与发布检查分别记录后再决定正式发布。

## 最小数据与状态契约

| 对象 | 契约 |
|---|---|
| repo/module | 配置登记稳定 ID 与服务边界；不以 basename 或 Java 包目录猜全局身份；无配置时回退仓级并提示 |
| source | repo_id + 规范化相对路径，附允许根、内容哈希、revision 和采集状态；文档更新时间/采集时间/复核时间与可信度分开存储 |
| entity | repo/module/owner/签名范围内的逻辑身份；源位置和修订另存。未解析构造保留独立候选，不能静默合并 |
| evidence | source_id + 内容版本 + locator + 抽取器版本；可引用前固定展示片段。在声明的保留期内可读旧版本，历史内容不可用时明确返回，不能拿当前文件冒充旧证据；被知识/审定引用的快照固定保留 |
| knowledge/review | 稳定 note_id、正文、修订、作者与理由、引用证据、审定与新鲜度；索引可重建，原始记录保留 |
| context | 可信 AGENTS/SOUL 的路径、作用域、哈希、预算与生效来源；普通搜索资料不自动升级为执行指令 |
| time policy | as_of/时区、日期依据、half_life、weight 与按类型关闭选项；按查询时点算降权，不修改事实或删除旧资料 |

重构或文件移动没有可靠映射时，允许历史引用保持并提示重新绑定；显式别名/重绑定事件不能自动继承旧审定。跨数据源同名表、跨消息系统同名 Topic 默认隔离，共享身份通过映射声明。

## 验收与反馈门槛

| 层次 | 如何验证 |
|---|---|
| 正确性，阻塞相应功能交付 | 不串身份/来源；无伪确定调用；图损坏可恢复；保存冲突与失败不丢记录；越界源不悄悄读入 |
| 机制 smoke，立即执行 | 合成反例与原 8 条夹具；gold 不来自待测图，仿造不存在 ID 的结果必须失败 |
| 检索质量，试点目标 | raw/scenario 分别报告 hit@5、MRR、误拒答；5 个主候选之外的扩展不补分；返回预算一致 |
| 任务质量，试点目标 | 独立留出集至少 20 需求、10 故障调查、20 困难负例；需求 hit@5 ≥80%，故障相关证据前 5 ≥7/10，负例正确保留判断 ≥19/20 |
| 领域导航，适用时验收 | 标注最多 100 服务，小样本则全量；准确率目标 ≥90%，未知/冲突不剔出分母；报告覆盖率 |
| 支撑与知识复用 | 分别看关键证据链完整率、引用真正支撑率、保存后再次命中与源变化后的提醒；不是只看链接存在 |
| AI 接入 | Claude/Codex/ZCode/DSH 分别记录新会话工具发现、检索、证据读取；幂等连接与受管配置撤销；无运行条件则保留待验收 |
| 人工搜索 | 无 AI 客户端/模型也能用 CLI 与只读页面；相同查询与 MCP 同源同序，可读出处 |
| 轻量人设 | AGENTS/SOUL 可查看生效来源、修改后在目标客户端生效；缺失/超限有提示，不改变权限与事实引用 |
| 时间衰减 | 冻结 as_of 验证单调降权、日期未知、长期有效文档例外、复核版本、touch/复制、过期/替代与历史查询 |

开发/验收按来源或任务族隔离，避免同一 PRD 的改写同时出现在两边。gold 先标源位置、必要事实与允许目标，再映射冻结版本的 ID；不靠任意名称子串评分。
