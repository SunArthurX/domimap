# M1.2 有限解析试验记录：lite 正则基线 vs 直接 Java AST（javalang）

日期：2026-10-16 ｜ 输入：tests/fixtures/precision（重载/字段别名/空方法/lambda/匿名类）｜ 产物：out/verification/m1-ast-trial.json

## 固定版本与成本

- javalang==0.13.0（纯 Python，wheel ~101KB，零依赖；pip 安装秒级）。风险：上游 2019 年后无维护，Python 新版本兼容性需每次实测（本机 3.13 可装可跑）。
- tree-sitter-java：性能/维护更佳但需二进制轮子与绑定，违反核心零依赖约束，只能进可选 extra，暂不试验（记录为未测）。

## 同输入差异（方法抽取 / 调用归属）

| 维度 | lite（本切片后） | javalang AST |
|---|---|---|
| 方法签名 argc | 8/8 与 AST 一致（含重载 #2/#1、空方法） | 7（漏匿名类方法 `call()`——匿名类不在 ClassDeclaration 过滤器内） |
| lambda/匿名内调用 | 保守跳过 + coverage 显式记录（不假归属） | 归属外层方法 `outer`（结构上确在其体内）；匿名类方法本身丢失 |
| 重载 dispatch | 多候选 → AMBIGUOUS 边到每个候选（不默取） | 仍需类型推断才能消歧（AST 只给调用点，不给目标重载） |
| 顺带修复 | 裸调用行曾被当方法声明（空白类型段 bug，本切片修） | 不适用 |

## 决策（生产主路径）

**维持 lite 正则为生产主路径**：核心零依赖约束 + 当前已声明构造（路由/Mapper/RPC/MQ/JPA/重载签名/字段别名）上与 AST 方法抽取一致，且在歧义处显式 AMBIGUOUS 而非默取。javalang 记录为候选：当 M2+ 真实失败样本显示需要**类型级 dispatch/参数级数据流**时，以可选 extra 形式接入（固定 0.13.0，评估维护风险），不默认绑定。

## 未知项（不伪装为已支持）

- 跨行方法签名的 argc（当前记 -1 显式未知）；多重嵌套泛型匿名类；注释/字符串内的调用形态。
