# v0.5 A / WP1：来源身份与解析边界

状态：待实施的详细输入，归入[生产主计划 M1](../roadmap.md)。制定于 2026-10-16，最初依据[第三版路线](../archive/2026-10-16/plans/2026-10-16-v0.5-v0.8-知识库演进路线.md)。

当前先完成主计划 M0 工程基线；本执行单不独立构成整个 M1。实施需同时满足主计划新增的适用范围、来源家族、陈述兼容字段，以及事务元数据/代际发布契约，不能只改 ID 后跳过构建恢复。

## 要解决的问题

当前方法按 service+方法名合并，类和文档缺少足够范围；接收者按名字猜测，方法体使用后续 3000 字符。直接把这些结果接到人工笔记，会把错误来源和错误调用长期保存下来。

此包交付一个可供后续构建、检索和保存复用的最小契约，并迁移当前图；不承诺完整 Java 语义。

## 1. 固定失败案例

新增 `tests/test_identity_contracts.py` 与小型合成夹具，使用临时输出，不改已有业务样例的含义。

| 案例 | 必须满足 |
|---|---|
| 两仓同 FQN、同 basename 仓库 | 仓库可显式区分，两个类和来源都在 |
| 同仓两个模块同 FQN | 模块隔离，不能出现 A 的 file 搭 B 的 meta |
| Controller/Service 同名方法、方法重载 | 按 owner/签名区分；无法解析的候选也不合并 |
| 两仓同路径 README | 两份正文与各自来源都保留 |
| first 空、second 调 worker.work | first 无假调用；second 的证据只来自其范围 |
| worker 改名 dependency | 能按声明解析则连边，不能则标未知；不能伪造解析成功 |
| roots 输入顺序反转 | 规范化身份与证据集合相同 |

这些是预期行为，应先看到现有实现失败。不要把现有碰撞和串方法结果写入期望。

## 2. 写最小 schema 样例并审查依赖

新增 `docs/contracts/source-entity-evidence-v2.md`，定义以下逻辑内容；编码方式在实现时保持 stdlib 可读。

- 配置：显式 repo_id、可选 module/service 映射、允许根与排除路径；路径移动可重新绑定根，ID 不取本机绝对路径哈希。为可信 AGENTS.md / SOUL.md 路径、上下文预算和时间策略留明确配置，不把普通摄入的同名文件当作指令。
- Source：repo_id、规范化相对路径、content_hash、revision 或空、采集状态；文档自身更新时间、采集时间与日期可信度分开。人工复核时间在 WP4 绑定对应内容版本。
- Entity：逻辑身份、kind、owner、signature 或 provisional 标记、source_id、locator；区分同名与同一实体。
- Evidence：不可变的版本化来源引用、范围、固化展示片段及内容引用、抽取器版本与置信。首次生成可对外引用的 ID 前保存所需片段，支持无 Git 的仓；不可恢复的额外历史上下文明确返回不可用，不能读取当前文件冒充旧内容。
- Relation：源/目标 entity_id、类型、证据引用与推断依据；无法定位或解析的引用列为未解析记录。
- Schema：`domimap.graph.v2`；旧图拒绝误读并给出重建路径。历史证据按公开的保留期管理，被知识或审定引用的片段不得随重建删除；未来人工知识不在派生图清理范围。

用两份碰撞输入和一条重载/未解析输入写完整 JSON 示例，检查所有关系端点与证据引用存在，不能只罗列字段。

## 3. 受限解析验证后选最小路径

只对上述方法 owner/span/signature 与字段别名反例做比较：lite 基线、一个 Java AST 方案、一个经接口/部署筛选的现成后端。

记录候选固定版本、安装要求、输出字段、正确/错误/未知结果、来源定位与维护代价。先用官方接口和最小样例排除不合适者，不能为比较而建设完整三套适配器。

选择标准：同名与范围不误判、来源定位可验证、降级明确、部署可接受。没有候选满足时收缩支持范围，保留未知，不能把“有 AST”当成类型解析已正确。

本轮十次分析没有执行这项上游对比；它仍是实现工作的待办。

## 4. 迁移接线

预计触及：新增 `domimap/identity.py` 与最小配置读取模块；修改 `lite_scan.py`、`graph.py`、`batch.py`，同步 CLI/MCP 的来源字段；更新使用旧 ID 的 golden 断言。

采用单一标识生成入口，避免每个 synthesizer 自行拼 ID；图构建先注册实体再解析引用。不要只改节点 ID 而遗漏 SQL/MQ/路由/RPC 的引用端。

每个已有规则仍须表明 supported / unresolved / ambiguous；从未知推成确定关系的变更需要源位置支持。此包不补完全部 RPC、路由匹配和类型推断，其专门规则按主路线推进。
