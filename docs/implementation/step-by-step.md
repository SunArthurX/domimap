# M0–M5 逐步分析与优化执行单

日期：2026-10-16。这是[主计划](../roadmap.md)的细化；产品边界和最终验收由 [specs](../../specs/product.md)约束。以下各切片待实施，不因本文完成而算产品完成。

## 1. 先用第一性原理检查顺序

用户需要在可承受的使用和维护成本下形成正确、适用、能复核的理解。由此推出：

| 必要条件 | 不满足的后果 | 顺序决策 |
|---|---|---|
| 范围和来源正确 | 答案流畅但引用另一仓/版本 | 身份/范围先于排名优化 |
| 证据可读取 | 保存后无法再核对 | 固化先于对外返回 ID 和知识保存 |
| 更新与写入可靠 | 新索引污染旧数据或知识丢失 | 发布/事务先于长期积累 |
| 一条可用用户路径 | 设计不断扩大，无法反馈 | 在完整解析前交付正确子集与显式未知 |
| 知识可维护 | 初次好用，长期失效且没人能处理 | 保存/复核/恢复作为同一闭环 |
| 独立质量基线 | 最后才发现指标不可比或没有提升 | 比较协议、gold 与基线准备从 M0 开始 |
| 可执行的开发约束 | 各 Agent 以不同定义宣布完成 | 需求→案例→任务→证据→发布门槛形成链路 |

现有路线的问题是 M1/M2 包含过多独立风险，M0 混淆了协议小试与真正客户端联调，M5 质量门槛不足以证明高于竞品。优化保留全部需求，将每阶段拆成有输入/输出的小切片；比较要求提升为 R14 硬门槛。

## 2. M0：把工程和比较规则立住

**必须解决的问题**：代码尚无版本管理，烟雾测试和正式质量口径不同，后续 Agent 容易一边实现一边改完成定义。M0 不以最终产品功能通过为前置，否则无法启动。

### M0.1 现状、规格和版本基线

- 输入：当前源码、26 项原型/维护测试，以及新增规格和评分工具测试。
- 输出：Git 初始状态、需求/案例映射、实际缺陷清单、测试输出/源数据分离、首个小任务 spec/manifest。
- 当前已具备：清理工具、临时测试输出、Spec 基础设施。仍缺：Git/CI/发布基础与生产案例验证；不可把 M0 整体勾完。
- 验证：运行本地 verify；故意删除需求、伪造 verified 或改动任务范围外文件时检查器失败。不得以历史审计直接当本次状态。

### M0.2 比较协议、数据与运行器 spike

- 输入：四个官方产品与固定目标任务族；先选公开/许可来源。
- 输出：dev 与确认集隔离设计、canonical evidence/fact 标注规则、五系统公共输出、安装/健康检查与成本清单。
- 先用少量 dev 题验证每条适配路径，而非立即跑 400 题。保留原始结果及映射，公平设置各产品原生工作流。
- 验证：完整的 tiny dev 五系统回放能够评分；错 ID、漏系统、坏工件、不同预算和打平不能通过正式门槛。没有安装四产品时只能记未完成。
- 原理：如果主张无法在同一输入/判据下比较，先解决测量，不能后期拿宣传数字补缺口。

### M0.3 可安装、可维护的工程底线

- 输出：来源/许可证清单、贡献/安全/变更说明、核心/extras CI、净化工件清单、sdist/wheel 的干净环境安装。
- 测试真实安装位置与异目录启动，不能靠 cwd/PYTHONPATH 偶然成功。测试失败必须原样返回非零。
- 不借清理任务添加业务能力或自动上传。公开开发仓可与产品验收分开，必须先有合法、净化的实际文件集合。

### M0.4 最小接口与协议试验

- 输出：Query/Read/错误/配置版本的最小样例、MCP SDK 固定版本选择；四客户端实际产品/版本的接口调查表。
- 这里只证明 SDK/协议路径可行；实际证据查询与人设行为依赖 M2，ZCode/DSH 的未知接口保持未知。
- 完整数据库 schema 与所有框架规则不在这里一次冻结，只冻结跨切片必要不变量与可迁移边界。

**M0 出口**：工程可重复，规格和比较机制有可执行检查；不要求原型缺陷全消失，但进入相关产品切片前必须能暴露它们。源代码是否正确与测试工具是否正确分别审查。

## 3. M1：先把数据变可信

### M1.1 来源捕获与身份

- 输入：显式登记 workspace/repo/module/source 与允许根；同时支持纯文档目录。
- 输出：统一标识入口、同份捕获字节的 hash/解析输入、适用范围与 SourceVersion。路径移动可重绑，未知环境不猜。
- 反例：跨仓同名、两个 basename 相同的根、两模块同 FQN、同路径 README、顺序反转、越界文件链接。
- 涉及：identity/config/source 模块与扫描边界；不要同时替换全部查询和 UI。

### M1.2 定义/位置解析与关系接线

- 以 lite 作基线，小试一个直接 Java AST 和一个现成后端；用同一失败集记录正确/错误/未知、owner/span/signature、启动/依赖和许可成本。
- 选一条生产主路径；AST 不能自动保证类型解析正确。字段别名、重载与空方法边界必须正确；复杂派发可未解析，但不能合并成假确定边。
- 先登记所有实体，再解析 SQL/MQ/RPC/路由关系；命名空间包括服务、数据源、消息集群或明确未知。
- 验证：无 DDL Mapper 不漏既有读写语义；多 provider 不默取第一个。既有测试按正确语义迁移，不继续断言碰撞恰好发生。

### M1.3 固化证据与最小发布事务

- 输出：可读 excerpt/locator/source version、SQLite 元数据骨架、不可变 generation、active 指针。
- 必须按顺序完成：必要文件持久化→校验→事务登记/切换指针；文件系统与 SQLite 不天然构成一个原子事务。
- 验证：无 Git 修改/删源后旧 ID 不读当前内容；发布前中断保留旧代，提交后必要文件齐全；孤儿可回收但固定引用不可删。
- 知识存储字段只保留兼容接口，此时不创造临时笔记格式。

### M1.4 失效、恢复与基础 coverage

- 修复图丢失仍 no-op、坏缓存、root/label、种子/规则/配置未失效；验证删除/重命名、扫描中变更、两写者/磁盘满。
- 先保证正确全量和手动 update，比较规范化对象/关系/证据；真正增量复用、监听随后做。
- 读取失败、缺依赖、截断/超限、未支持构造进入 coverage；不能把静默跳过当成资料不存在。

**M1 出口**：来源不串、证据可读、坏构建可恢复。可在此做内部 Query/Read 验证，但面向人的完整体验进入 M2，人工知识进入 M3。

## 4. M2：把可信材料交给人和 Agent

### M2.1 公共查询与分路召回

- 输入：M1 的来源/图/片段与最小结果契约。
- 输出：代码与文档独立召回、范围筛选、来源家族去重、完整证据包、稳定错误与缺口；CLI/MCP 调同一服务。
- 反例：代码占 Top-K 导致文档消失、复制文件占榜、只有领域词、同名不同版本。词法/精确符号作为可解释基线，先测失败再决定向量。
- 验证 raw 主候选，扩展、scenario、最终答案分开统计。

### M2.2 Read/Trace 与执行预算

- 证据按 ID 读取；定位问题默认不扩全图，关系问题按方向追踪。
- 上限在遍历前执行：节点、边、深度、耗时、返回量；超限返回 partial 和未覆盖范围。引用按完整项输出。
- 反例：高出度、MQ 消费者漏报、Domain 变成调用依赖、缺源/未知派发。路径置信不能强于最弱一边。

### M2.3 人工页面和第一条真实 Agent 路径

- 先做可安装的只读 UI：输入、筛选、结果、原文、范围、缺口；不先建设全图展示/聊天窗口。
- 在一个真实可运行客户端完成发现→搜索→读取，再完成第二个。连接配置预览/幂等/受管撤销与运行路径诊断同时做。
- 没模型也能人工使用；UI/MCP 同请求同序。mock 用于故障测试，不能代替真实客户端证据。

### M2.4 上下文、文档时间与首批任务

- 可信 AGENTS/SOUL 与业务资料隔离，作用域/哈希/预算可看；宿主桥接不越权。
- 时间先处理生效/撤回/替代，再降权时间敏感的合格资料；未知日期与长期规范可解释，touch 不刷新。
- 收集十条真实任务，只作为发现问题与成本观察。用 dev 五系统回放定位差距，不读确认 gold 调参。

**M2 出口**：可搜索、可读证据、真实 Agent 能用；不是知识库长期维护已完成。此时可发布真实标注边界的技术预览。

## 5. M3：让每次使用能积累，并能被纠正

### M3.1 事务化的单条知识与 claims

- 输出：note/claim/revision、支持/反对证据、适用范围和类型；草稿可手工提交，不强制 LLM 自动拆所有资料。
- 最小原子提交同时更新正文、引用、审定/依赖和检索可见性；延迟索引则明确 pending 并可读已提交版本。
- 无证据说明可保存为决策/假设，但不能声称源码验证。先满足该边界，再做批量综合。

### M3.2 幂等、冲突与审定

- expected_revision 防止覆盖；同幂等键同内容返回同一结果，不同内容冲突；超时后能查提交是否成功。
- 人工接受与抽取性质独立；源 hash/范围/规则改变不继承旧复核。查询不默写，明确保存指令无需反复确认。
- 反例：双会话编辑、重复保存、提交中断、审定推断被改成 extracted。

### M3.3 变更到复核闭环

- 依赖 source/evidence/配置→claim；变更时列旧结论、变化和受影响部分。
- 只让受影响陈述待复核，重复扫描合并事项；优先处理常用且依据已变的内容。
- 三个动作：确认并绑定新依据、修改/替代、撤回。点击和使用频率只能表示价值，不能刷新真实性。

### M3.4 可带走、可恢复、可人工维护

- 导出知识/历史/审定/范围/固定证据；运行中采用受支持在线备份，空目录恢复后验证，不只检查 zip 存在。
- MD/Obsidian 先明确导入/导出，SQLite 为权威数据；外部编辑检查 base_revision，不能两边都静默自动覆盖。
- 本地 UI 完成保存/复核/恢复必要操作；至少十条知识完成跨会话全循环。保留/删除策略与恢复一同验收。

**M3 出口**：积累与维护都可完成，机器重建不影响人工知识。真正知识收益在此才可用重复任务测量。

## 6. M4：补齐完整支持并加固运行

M4 在 M2 后可独立推进；M3/M4 最终都必须完成，不允许以“并行”永久跳过任一条。

### M4.1 四客户端逐项兑现

- Claude/Codex/ZCode/DSH 各有产品、版本、原生配置、发现/读取/上下文/撤销记录。
- 调查不明的 ZCode/DSH 可请求所需版本/接口样本；继续其他工作，但不能以通用 CLI 结项。
- 路径含空格、跨目录启动、升级、移动知识库与配置冲突都是反例。

### M4.2 格式和框架覆盖矩阵

- PDF/DOCX extras：缺依赖、损坏、加密、无文本和超限分开；页/段落与片段可核对。
- Java/框架按构造列支持/部分/未知：动态 SQL、RPC 多 provider、MQ role/cluster、JPA 和 HTTP method/路由范围。
- 不为抬覆盖率默连边；按照真实失败补解析，能力范围必须公开，不承诺纯静态根因。

### M4.3 更新、并发和安全压力

- 在正确手动更新上做仓记录复用；可选监听需要事件合并、漏事件/溢出/分支切换与重扫恢复。
- 四客户端八在途读取与串行写/发布，检查锁超时、取消、缓存竞争和回收在读代。
- 全入口统一根目录、MCP 容错、网页安全呈现/Origin/CSRF 和写权限；任何适配器都不能绕公共边界。

### M4.4 平台、迁移和资源

- 按实际声明 OS/Python/extras 安装、运行、升级/失败回退；文件锁/同步与本地文件系统限制写清楚。
- 在预登记输入与硬件上测冷/热、峰值内存、磁盘增长；不能用截掉必要证据或忽略错误来过性能线。
- 先修已确认瓶颈；图数据库、向量、更多后端只有证据触发时引入。

**M4 出口**：所有明确入口/格式/平台承诺可复查。缺运行环境仍为待验收，而非“设计支持”。

## 7. M5：确认收益与最终交付

### M5.1 冻结 RC 与确认批次

- 在看确认题结果前固定源指纹/提交、模型、五系统版本/预算、gold、cluster、种子和统计方法。
- 开发者不读取确认 gold。准备好独立运行器、盲化判定、哈希工件及基线健康检查。
- 竞品安装/运行未完成时是阻塞，不能降低其分数；先做 dev 试验避免浪费正式批次。

### M5.2 执行三指标严格比较

- 至少 300 可回答、100 不可直接回答、20 cluster、五种子；四类可回答题各不少于 50。
- Hit@5、任务 Accuracy、事实 micro-F1 全部对四个竞品逐一胜出，12 个差值的修正下界 >0，绝对底线和负例处理同时满足。
- 打平、竞品达 100%、证据不足都不通过。开发改进使用 dev；需要新确认批次时按预登记/独立集控制多次检验。

### M5.3 生产故障与恢复演练

- 已知身份/历史引用/丢写/越界错误为零；真实负载至少 24h，公开候选预算冻结后的结果。
- 迁移/回退、10,000 条知识恢复、实际包下四客户端与本地 UI/知识闭环均需证据。
- 质量高不能豁免数据丢失，性能快不能豁免错误答案；各自 gate 独立。

### M5.4 对照规格收敛和发布准备

- 逐案例核对源码、当前指纹、命令、原始工件、环境、未覆盖项；运行 release-check。
- 净化源码/历史/分发物/日志与截图，补支持矩阵、许可证、升级/备份说明、SHA-256 和比较报告。
- 用户未授权发布时完成本地可审查分发物和全部验收，保留上传为外部动作；不能因此声称已经上线。

**M5 出口**：所有需求/案例与四竞品比较同时满足。任何未完成都准确列出，不能以“prompt 已写好”或“所有单元测试通过”代替生产完成。

## 8. 诊断和持续开发决策

| 失败位置 | 先检查 | 不应直接采取的动作 |
|---|---|---|
| 找不到必要证据 | 摄入/覆盖/分片、范围、召回 | 立即换更大模型 |
| 找到但排不到前五 | 去重、别名、融合、排序解释 | 把 Top-10 偷换成 Top-5 |
| 引用错误或不适用 | 内容版本、locator、canonical 映射、范围 | 按名字相似算命中 |
| 结论错误 | 必要事实/证据链/冲突/生成指令 | 只增加返回字数 |
| 旧知识继续被当当前 | 有效期/依赖/复核版本 | 只加统一年龄惩罚 |
| 保存/构建失败 | 事务、发布顺序、幂等、恢复 | 先做监听加快错误传播 |
| 竞品未运行或结果不可比 | 安装/预算/宿主/模型/适配 | 拿宣传指标或零分替代 |
| 统计不能证明差异 | 独立样本、方差、效应大小 | 反复偷看同一留出集调参 |

先定位故障层，再选择最小但满足原目标的修复。完整范围保持不变，切片用于降低实现风险，而非降低完成标准。
