# 四项能力补充计划：AI 接入、人工搜索、轻量人设、时间衰减

状态：**已纳入路线，待实现的部分未勾选**。日期：2026-10-16。

> 2026-10-27 快照：四能力的基础设施已到位——`domimap connect/disconnect/clients`（四客户端原生配置）、CLI/UI/MCP 无模型检索（含 `--as-of` 历史范围与拒答原因）、`trust add`+`domimap context`+MCP `kg_context`（可信上下文，嵌套裁决/变更检测）、时间策略（过期/被替代默认不具资格、内容纪元、复制不刷新）。真实客户端会话验收仍按各 F1 案例如实待外部条件（Claude 已实测关闭 AC-F1-C1-01/02）。逐例见 specs/progress.json。

对应用户明确要求：快速接入 Claude / Codex / ZCode / DSH，人工手动搜索，AGENTS.md 与轻量 SOUL.md 定制，以及文档时间衰减。当前执行阶段以[生产级知识库主计划](roadmap.md)为准，本文保留详细交互与时间策略需求。

下文 WP 编号沿用原安排，映射为：WP1/WP2 的数据契约归 M1；WP3 公共检索、人工搜索、上下文和时间排序归 M2；WP4 人工知识与复核归 M3；四客户端完整适配及格式/运行加固归 M4；完整发布验收归 M5。四项能力都必须留下实际验证，不能以计划整合代替。

## F1：快速接入四类 Code Agent（WP3）

首版连接本机客户端；优先复用同一 MCP stdio 服务，支持通过客户端现有扩展机制调用 CLI 的适配路径。不同客户端分别提供适配器和验收记录，不能把一个客户端的配置原样用于另一个。

| 目标客户端 | 接入设计依据 | domimap 当前验收状态 |
|---|---|---|
| Claude Code | 官方 MCP 本地进程接口；按安装版本识别配置范围和指令文件机制 | 未联调；已有示例不等于快速接入完成 |
| Codex | 官方 stdio MCP；独立生成其 TOML 配置或使用其配置命令 | 未联调；不能复用 Claude 的 JSON 当作 Codex 配置 |
| ZCode | 实施前核对用户实际版本的 MCP / 扩展 / 工具接口及指令入口 | 待核对接口，不宣称兼容 |
| DSH Code Agent | 实施前核对用户实际版本的 MCP / 扩展 / 工具接口及指令入口 | 待核对接口，不宣称兼容 |

ZCode/DSH 仍是明确的交付目标。接口未核实时提供 CLI 使用说明便于先用，但 **CLI 可运行不能代替这两个客户端的接入验收**。它们的联调记录与公共检索核心分别跟踪，不阻塞知识保存核心的开发。

- [x] `domimap connect <claude|codex|zcode|dsh>`（2026-10-26 connect-clients）：按各客户端实测原生接口生成配置、幂等接入、写前备份、受管撤销（`disconnect`）、诊断（`clients`）；图路径/解释器/PYTHONPATH 写入条目，支持空格路径。真实会话验收（AC-F1-C*）仍需各客户端新会话记录。
- [ ] 提供 `--dry-run`、幂等合并和撤销本工具所加条目的能力；保留现有 MCP、项目规则和其他配置。显式执行连接命令即处理选定配置，不另设重复确认；涉及宿主信任设置时显示其原生要求，不能绕过。
- [ ] 新增连接诊断：初始化 → 工具发现 → 搜索样例 → 读取来源；显示客户端版本、transport、知识库 snapshot、失败原因及修复办法。仅有配置文件不算连接成功。
- [ ] 生成短小的“何时查知识库、如何引用、缺证据怎样说明”指引，放到客户端实际加载的入口；绑定下述 F3 上下文加载，不要求用户每次粘贴长提示词。

**验收**：每个具备运行条件的目标客户端，在新会话里能发现 domimap、根据指引检索并读取一个真实存在的证据；重复连接不重复写配置，撤销只移除受管条目。尚未具备实际版本/接口样本的客户端明确记待验收，不能标已支持。工作区路径移动、缺依赖、图不存在分别给可操作提示。

官方依据：[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、[Claude Code MCP](https://code.claude.com/docs/en/mcp)。两者均提供本地进程接入，但客户端具有不同配置与信任机制。此处采用它们的接入契约，不代表 domimap 已通过联调。

## F2：人工手动搜索（现有 CLI 保留，WP3 补体验）

现在可用：

```bash
python3 -m domimap query "订单改价 price_version" -g out/mini/graph.json
python3 -m domimap query "price_version" --domain 订单域 -g out/mini/graph.json
```

以下为后续交付：

- [ ] CLI 增加结构化输出与来源类型/仓库/时间筛选，保留自然语言查询、符号查询和领域导航；复用与 MCP 相同的查询契约、证据与时间策略。
- [ ] 计划新增 `domimap ui` 本地只读搜索页：搜索框、结果列表、来源片段、仓库/类型/领域筛选、更新时间与“可能过时”提示；无匹配时说明范围与缺口。
- [ ] 搜索页在无需 AI 客户端、模型或 API Key 时也能工作，默认仅监听本机回环地址；来源阅读限登记根或保存的证据快照。

WP3 先交付可用的只读页面，WP6 再做完整知识编辑与审定体验；主链可在公共检索核心就绪后进入 WP4，不等全部界面润色。

**验收**：人工与 MCP 用相同请求得到相同主候选、引用与时间标签；人能打开命中的原文片段。空查询、无匹配、失效来源和日期未知有明确状态。现有 CLI 搜索在新增界面后继续可用。

## F3：AGENTS.md 与 SOUL.md 轻量定制（WP1 配置，WP3 生效）

只引入两个可选 Markdown 文件和少量结构化偏好，不引入独立 Agent 运行时、自动人格演化、聊天渠道或多代理编排。

| 文件/配置 | 职责 |
|---|---|
| 选定工作区的 `AGENTS.md` | 知识库使用规则：先查证据、引用方式、未知项说明、保存与复核习惯 |
| 选定的 `SOUL.md` | 人设与表达：角色、语言、语气、回答详略；默认模板简短，可直接编辑 |
| `domimap.json` | 知识库路径、可信上下文文件、查询偏好、时间策略等确定性参数 |

- [x] WP1 登记显式可信工作区和上下文路径；只读取选定根的规则文件。嵌套 AGENTS 只在对应任务范围内适用，不拼接所有仓库的规则。搜索摄入的同名文件默认只是来源资料，不能自动成为执行指令。（2026-10-26 trusted-context：`domimap trust add/list/remove`、`domimap context [--scope]`、MCP `kg_context`；信任无默认、scope 向上最近一层生效、sha 变更检测、预算超限显式丢弃清单。四客户端桥接生效验证 AC-F3-02 仍待 T14。）
- [ ] 计划新增 `domimap context init/show`：缺失时生成简短模板，已有文件保留；输出实际采用的文件、作用域、版本/哈希与裁剪情况。默认上下文总预算 6000 字符，可配置；按完整段落选择，超长单条规则明确提示，不能静默截断或跳过。指令文件哈希单独校验，变更不依赖 graph.json 更新或重新建图。
- [ ] 新增只读 MCP `kg_context` 返回解析后的规则与人设及来源。连接指引要求在首次知识库任务时取得上下文；能通过原生指令文件加载的客户端使用其原生入口，避免重复注入。
- [ ] 对 Codex 的 AGENTS 机制与 Claude 的实际指令加载机制分别做适配。`SOUL.md` 是 domimap 的轻量约定，不能宣称所有宿主原生识别；通过明确导入或上下文工具桥接。
- [ ] 结构化查询参数按“显式请求 > 工作区配置 > 内置默认”解析；Markdown 人设只塑造回答，不扩大读取根、写入权限或网络能力，不覆盖宿主更高层指令。普通检索不自动改写 AGENTS/SOUL。

**验收**：修改 SOUL 后，新会话可表现出选定语言/详略；修改 AGENTS 后，证据引用和未知说明规则在目标客户端的样例任务中生效。只读检索的 ID/来源不会因人格改变而变造；日期筛选等确定性行为以配置和显式请求为准。跨仓不串规则、文件缺失能回退、超限有提示；CLI 人工搜索也能查看当前上下文状态。

官方参考：[Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Claude 指令文件](https://code.claude.com/docs/en/memory)。借鉴 [Hermes 文件职责](https://hermes-agent.nousresearch.com/docs/user-guide/which-file-does-what)与 [OpenClaw 工作区](https://docs.openclaw.ai/concepts/agent-workspace)中规则和人设分文件的方式，不复制它们的完整运行时。宿主加载方式随版本核对，MCP 服务本身不能强制客户端采用提示词。

## F4：文档时间衰减（WP2 时间字段，WP3 排序，WP4 复核）

年龄、来源是否改变、是否被替代、人是否审定分别记录。时间降权用于提示“可能过时”，不自动删除资料，也不把旧资料直接判错。

### 时间字段与日期依据

- [ ] WP2 采集文档类型、声明的生效/更新时间、采集时间及其来源可信度；WP4 增加 `last_verified_at` 与对应内容哈希、可选 `valid_from` / `valid_until`、`superseded_by`。日期缺失或冲突可表示 unknown，不能编造。
- [ ] 衰减日期优先使用绑定当前内容版本的人工复核时间，其次可信的文档自身更新/生效时间或可确认的内容修订时间。文件 mtime 仅作为低可信线索，不能单独用作 freshness_basis；只有 mtime 时标日期未知。复制、touch、重新扫描、查询次数和索引重建不得把旧内容变成刚复核。
- [ ] 明确 superseded、withdrawn 或已超有效期的内容，默认不作当前结论依据；历史查询仍能找到并显示适用范围。来源内容变化时旧复核不继承到新版本。
- [ ] 明确尚未生效的资料不作当前有效依据；不能核实的未来更新时间按日期未知处理，不给“最新”优势。时间戳统一存 UTC，日期值按工作区配置的时区解释，查询 `as_of` 使用同一规则。

### 轻量排序策略

首先满足来源范围、相关性与支撑要求，然后仅对时间敏感的文档/知识结果加衰减；源码符号精确匹配不因文件年龄降权。

起始配置候选（待试点调整）：

```text
age = max(0, as_of - freshness_basis)
factor = 1 - weight + weight * 2 ** (-age_days / half_life_days)
score = relevance_score * factor
```

建议先试 `half_life_days=90`、`weight=0.2`：日期为今天时因子 1，90 天为 0.9，180 天为 0.85，长期趋于 0.8。它是本产品待校准的起始参数，不是行业通用阈值。允许按文档类型关闭或调整；例如明确有效的长期规范可不衰减。

- [ ] 无可靠日期时不当作今天更新；使用明确标识的中性策略，首版因子固定为 0.9，并显示“日期未知”。过期/被替代的硬状态优先于分数和新鲜度，不因缺日期而解除。
- [ ] CLI/MCP/UI 共用策略与时区，提供确定的 `as_of` 和关闭衰减选项；按查询时间计算，不把最终衰减分数永久缓存。返回日期依据、age、因子与“可能过时”原因；用户界面只呈现便于理解的日期与状态。
- [ ] 时间阈值筛选区分文档更新时间、复核时间和采集时间；不能把“最近导入”默认当成“最近有效”。

**验收**：冻结查询日期、同等相关性下更久未复核的时间敏感资料得分不升；过 90 天因子符合公式且无需重建；明确有效的长期文档不被强行降权；复制/touch/重建不刷新复核；改变内容后旧复核失效；未知日期、未来日期、过期、被替代与历史查询都有案例。使用日期或人设不能绕过证据支撑要求。

## 依赖与完成定义

| 阶段 | 本补充中的交付 |
|---|---|
| WP1 | 上下文可信路径与配置契约；证据从首次对外引用起可按版本读取 |
| WP2 | 时间元数据、历史证据留存与更新/缓存失效 |

| WP4 | 人工知识通道接入、复核时间与版本绑定、保存后再检索 |
| WP6 | 完整编辑/审定界面与平台发布体验 |

人工知识尚未建立前，WP3 只定义其检索扩展接口，不临时创造另一套笔记格式。历史证据从首次生成可引用 ID 起固定展示片段；未固定的历史上下文返回明确不可用，不读取现版本冒充旧版本。被知识/人审引用的快照不随索引重建清理；其他快照保留期必须可配置并公开说明。

上述 F1–F4 都有独立验收项。完成计划补充不等于功能完成；尤其四客户端联调、人设生效与时间排序必须分别留下实际记录。
