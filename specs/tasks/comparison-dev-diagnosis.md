# comparison-dev-diagnosis：开发集诊断与差距归因（测试计划第 5 步）

来源：计划 §9 步骤 5、§10（未达标时如何提升产品）。
性质：**评测基础设施 + 诊断执行**；随后按证据进入有界产品改进（另立任务）。

## 目标

对 40 题试跑批（diag-c9990b4d7bd8）的 200 条记录，用 dev-gold-v2 做路径级判定：
1. Hit@5（正例：top5 任一路径命中 gold 路径；族前缀 + 仓内相对路径直配）。
2. 负例正确处理率（正确=空结果拒答）。
3. 分层：系统 × 类别（四类 + locator 单列 + 负例）。
4. domimap 未命中归因：摄入（图节点无该文件）/ 召回（top50 无）/ 排序（6..50 命中）/ 类别维度（跨仓、时效）。

## 设计

`benchmarks/runners/dev_score.py`：读批次记录 + gold + questions →
`out/diagnostic-runs/pilot-score-v1.json`（矩阵 + domimap miss 表 + 差距清单）。
归因用同批次工件：domimap-idx/graph.json（摄入检查）、Searcher top_k=50 重查（召回/排序区分）。

## 契约（测试，合成记录）

1. 命中判定：top5 任一 == gold 路径 → hit；族前缀不匹配不算。
2. 负例：空 top5 记负例正确；非空记错误。
3. 分层矩阵行=系统、列=类别；locator 单列。
4. 归因三分支（摄入/召回/排序）互斥且必居其一（对 miss）。
5. 确定性。

## 回退

单提交回滚；评分工件在 out/ 可重生成。

## 边界

- 路径级 Hit@5 是**诊断轨**口径（非主轨任务 Accuracy/F1）；不用于宣称胜出。
- 诊断结论只驱动 dev 侧有界改进；确认侧仍独立。
