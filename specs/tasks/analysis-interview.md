# 项目原理与面试讲解资料

日期：2026-10-25。性质：只读源码分析与文档/交互图交付，不改变产品行为，不完成生产阶段。

## 问题、关联与边界

用户需要详解项目，用 C4 与 5W2H 组织原理，附有交互的 Mermaid/SVG、知识讲解、面试追问和答案。覆盖 R01–R14、F1-C1–C4/F2–F4；44 个验收案例用于解释范围与真实状态，本文档验收不等同于产品案例通过。

以当前含已有未提交修改的工作区为对象；规范优先于架构计划，源码决定“当前实现”的描述。保留已有修改和历史工件。只读取核心源码、公开/合成夹具、活动规范和开发工具；不读取确认集问题、gold、私有来源快照、密钥或模型配置。

## 输入输出与契约

- 输入：产品/工作流/要求/验收/progress/比较协议、主计划、当前源码与已有测试定义。
- 输出：`out/project-analysis/guide.md`、离线 `index.html`、Mermaid 源与预渲染 SVG、源码定位清单、交互/链接/可视化 QA 和交接。会话内补一幅可选择层级和节点的紧凑图。
- 图遵循 C4 语义；Container 是应用/数据存储，不等同于 Docker。C4 L3 限定一个核心应用，L4 限定 EvidenceStore 组件。补动态、数据及发布图，避免把它们当作另一个 C4 层级。
- 当前实现/规范目标/本次实测/分析建议显式区分；示例与模拟不声称真实业务/性能/竞品结果。
- HTML 交互仅操作资料本身；无 API、无模型调用、无上传。Mermaid 固定版本离线预渲染，以安全配置与自有事件绑定实现节点展开、缩放、导出和键盘等价控制。
- 源码引用绑定路径、符号、行号和 SHA-256；工作区变化后提示重新核对。
- 文档任务改变活动 spec 指纹，已 verified 的两项案例必须真实重跑其直接回归并保存新的独立证据，保留旧工件；其余案例不升级。

## 正例与负例

1. Given 原型与目标文档存在差异，When 阅读日期/身份/MCP/备份章节，Then 能同时找到当前代码和目标差距，不能宣称生产就绪。
2. Given C4 图，When 切换四层/点击节点/键盘选择节点/缩放/导出，Then 图和详情一致、导出的 SVG 可离线读取。
3. Given 所有外部网络被阻断，When 打开 HTML，Then 正文、图和问答仍可用。
4. Given 手机宽度与桌面宽度，When 阅读和搜索，Then 无正文横向溢出，图在独立视口中缩放，控件有可访问标签。
5. Given 面试问答，When 筛选与翻答，Then 不出现虚构个人贡献、用户规模、性能数据或比较胜出。
6. Given 当前已有未提交修改，When 检查本任务增量，Then 初始文件摘要除 progress 外不改变，不借文档任务修改产品。

## 验证、回退、缺口

按顺序：记录基线 → 读源码与规范 → 写资料 → Mermaid 实际渲染 → 浏览器离线交互/响应式/导出/内容引用检查 → 直接案例回归与证据 → `make verify` → `make release-check`。

任务结构检查不冒充相对 HEAD 的独立任务 diff：HEAD 已有其他工作。通过初始文件 SHA-256 与结束时对照验证任务边界，保留原始 git status。发布门禁必须继续因生产案例未齐而失败，不修改门槛。回退只移除本任务新增 spec/输出及 progress 的本任务元数据，证据历史保留。

交付状态与命令/工件哈希见同名 manifest 的 verification_evidence；交接写 `out/project-analysis/handoff.md`，并在 `out/handoff.md` 顶部添加指向本次交接的摘要。
