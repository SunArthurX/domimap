# 四竞品比较与最终质量验收 v1

日期：2026-10-16。状态：**强制的未来验收协议；当前未运行比较**。参数见 [protocol.json](../benchmarks/protocol.json)，评分实现见 [evaluate.py](../benchmarks/evaluate.py)。

## 1. 用户要求与可证明边界

最终必须在冻结的目标任务集上，使 domimap 的 **Hit@5、任务 Accuracy、事实 micro-F1** 各自高于以下每一个竞品；不是平均赢、只赢一项、只挑最弱基线，也不把缺结果算零。

| 固定比较对象 | 官方来源 | 比较准备 |
|---|---|---|
| claude-obsidian | [AgriciDaniel/claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) | 按正式能力安装知识工作流，不将其假装成裸代码解析器 |
| Codebase-Memory-MCP | [DeusData/codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) | 固定持久代码图与实际 MCP 运行版本 |
| CodeGraph | [colbymchenry/codegraph](https://github.com/colbymchenry/codegraph) | 固定其检索/源码阅读路径和配置 |
| Graphify | [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) | 固定代码/资料工作流、实际分支和提交 |

官方资料用于核对安装/能力，宣传的速度、token 或质量数字不直接作本项目结果。比较时记录不可变 commit/发布物哈希、依赖、原生配置与实际工具。若任一竞品达到 1.0，严格高于在该指标上不可达：**目标未达成**，不能改成打平也算赢或偷偷换题。

这是一项研发/发布目标，提示词不能保证算法必然达到。结论只适用于报告中的数据、版本、模型和预算，不能推广为所有语言、所有知识库或所有未来版本都更好。

## 2. 两类轨道，禁止混算

**主轨：用户任务端到端比较。** 五个系统分别配同一冻结 Agent 宿主、模型/版本、温度/随机种子、公共任务提示、来源资料和资源预算，使用各产品的正式工作流。最终输出同一答案/陈述/证据格式，计算三项主要指标。这使知识工作流与代码图工具在真实目标任务上可比较。

工具自带提示/检索方法可不同，但在 dev 集独立校准后固定；同样的文档阅读预算和人工配置时间给每个产品。允许的基础读文件能力、是否允许无工具回退、上下文/生成预算和停止条件必须对所有系统一致并预登记。外部模型 API 必须由同一模型快照提供，云模型不可冻结时记录限制。

种子同时作为共同重复编号；模型接口不支持 seed 时记录该限制，保持其余参数一致并完成五次实际运行，不伪造可控随机性。先用 tiny dev 估算成本，在已授权资源/预算内执行；资源不足保持未完成，不能缩小正式分母或自动购买额外额度。

**诊断轨：原生检索/解析/性能与能力交集。** raw Hit@5、代码符号/关系 precision/recall、只文本/加图/加人工知识消融、延迟/token 单独报告。原生工具没有同语义接口时列不适用，不能用主轨代理数字冒充其原生指标，也不能用诊断轨取代主轨的四竞品全量目标。

不支持某类任务但产品实际运行后给出 unsupported 属于覆盖结果，保留在端到端分母；未安装、接口不明、执行环境坏了属于 **比较未完成**，不能人为给对手零分。必须先尽合理安装/配置排障并保留记录。

## 3. 数据集与冻结

1. M0 建 dev 集与标注/适配 smoke，M2 开始真实任务；旧 8 题与 50 题试点用于开发，不能证明优于竞品。
2. 最终至少 **300 可回答 + 100 不可直接回答**任务，覆盖至少 **20 个独立工作区/项目族 cluster**。同仓、派生仓、同文档的改写、同业务家族归入同 cluster，禁止当独立样本扩 N。
3. 至少覆盖代码定位、跨仓/框架追踪、文档理解、知识复用/时效四类；各类至少 50 道可回答题。包含中英文/中文业务问法、重载/同名、多版本、冲突、重复、缺解析、无证据、删除/过期/草稿。
4. 来源必须有合法使用与分发依据；真实材料可留私有，只公开净化清单、哈希和可重现的公开子集。不得将私人源码上传模型或 GitHub 而未获适用授权。
5. dev / confirmation 按来源族隔离。最终确认题与 gold 在独立评测环境，开发 Agent 不读；实现者只能看 dev 与正式确认的汇总结论。不能从确认细节反复调参再对同一集声称留出验证。
6. 冻结前登记问题、范围、必要事实、可接受额外事实、证据位置/原文/版本、所需证据组、正确答复方式 answer/abstain/clarify。gold 不从 domimap 结果派生，不使用任意名称子串。
7. 固定数据/标注/协议/预算/基线/模型版本与 SHA-256；在运行前保留预登记记录。标签纠错对全部系统同等生效，旧 run 作废并新版本重跑；不得只修掉对自己不利的题。

样本下限是工程要求而非统计功效保证；效果差距很小时仍可能证据不足。追加新确认批次要先登记，不能无约束地逐次偷看直到显著；多次中期/最终检验需要预分配 alpha 或采用新的独立确认集。

## 4. 中立适配、证据与标注

公共问题提示要求：回答适用范围、必要结论、原文引用、未知项，并返回最多五个排序主证据和独立的支撑引用列表。不能输出 gold ID；canonical ID 由盲化标注/位置映射赋予。

证据以来源版本、路径/位置、原文引用匹配独立 canonical unit；对各工具保存原始输出到映射的记录。文件路径存在不等于引用支持；整仓/整文件不能充当一条无界证据。每项可读预算、上下文/locator 坐标和等价片段规则先冻结。

陈述由两个不见系统名的标注者核对必要事实、范围、支持和错误；分歧裁决并报告一致性。模型裁判可辅助 dev，但最终涉及支持/冲突的争议需独立人工抽查/裁决，保留判定依据。评分器不能仅相信模型自称正确。

每条记录含 system/case/seed、status、排序证据、支撑证据、已裁决事实 IDs、答复方式、scope_correct、unsupported_material_claim、原始结果与裁决工件 ID。unsupported_fact_ids 必须列出对应的不支持陈述且包含于预测事实；不能只设一个布尔值而漏掉 FP。即使内容听起来正确，没有支撑也不能获得该必要事实的 TP。使用工具自身 ID 无法映射时，不能猜为命中。

## 5. 三项指标的精确定义

设可回答任务集合 A，全部任务 Q；每个题/系统执行同样的 5 个种子。

### Hit@5：找到至少一项主要依据

只取最终排序主证据的前 5 个位置，再去重；先重复再去重不会释放额外名额。是否与独立标注的主要证据组有交集。主指标对 A 计算，跨种子平均；扩展项、第 6–10 项、卡片里出现答案词不能补分。完整证据链另在 Accuracy 中要求。

### Accuracy：任务答案完整、正确、适用且有支撑

每个题只能 0 或 1：实际运行成功、答复方式符合 gold、范围正确、所有必要事实成立、无错误/不支持的实质性陈述、每个必要证据组有引用。不可直接回答题应恰当地 abstain/clarify；系统超时/失败不能因空答案被当正确拒答。

Accuracy 是全部 Q 的上述通过比例，不是检索 precision、评测器自评分或无关二分类 TN 比例。可回答/不可回答、类别与语言同时分层报告。

### Fact micro-F1：必要事实的覆盖与错误代价

- TP = 预测事实与必要 gold 事实交集。
- FP = 预测中错误、不支持或不适用的事实；独立 gold 预登记的可接受额外事实不加 TP，也不算 FP。
- FN = 未覆盖的必要事实。重复事实只计一次；错误版本即使名字相同也不能计 TP。
- `micro-F1 = 2ΣTP / (2ΣTP + ΣFP + ΣFN)`，precision/recall 同时报告。正确空拒答不制造 TP；错误拒答仍损失可回答题 FN。失败运行按空事实处理并计任务错误，不排除分母。

分母为零时 F1 不可判定，不能设 1；最终集要求充分正例。macro-F1 与各类 F1 另报，不以大量简单短事实掩盖长链失败。合法额外事实由独立 gold/裁决确定，不能由待测 Agent 自行标 neutral。

## 6. 成对比较与最终判定

同一题/种子对齐五系统，固定至少 5 次重复，按 cluster 成对 bootstrap，默认 20,000 次。不要把同仓改写/五次模型输出当五倍独立样本。点估计用全部配对记录；micro-F1 在重采样后重新汇总 TP/FP/FN。

重采样若出现指标分母为零则重抽，最多尝试目标次数的十倍；不足有效样本时统计门槛未完成，不能以零/一补齐。

比较 4 基线 × 3 主指标，共 12 项。使用单侧家族 alpha=0.05，Bonferroni 的每项 alpha=0.05/12，报告差值与对应下界。多重比较控制的依据可参考 [NIST Bonferroni 说明](https://www.itl.nist.gov/div898/handbook/toolaids/pff/prc.pdf)。cluster percentile bootstrap 的覆盖是近似的，依赖样本代表性/cluster 划分；不能据此宣称任意分布的数学保证。

最终 **全部** 满足才 pass：

1. 五系统、所有题与种子真实运行完整，版本/预算/数据/标注一致可追溯；无遗漏、无模拟正式结果。
2. 样本/类别/cluster 数满足下限；独立 gold 和预登记/审查工件可核对。
3. domimap 的每项点估计严格高于每个竞品，12 个差值的修正单侧下界均 >0。
4. domimap 的工程底线：Hit@5 ≥0.80、Accuracy ≥0.85、micro-F1 ≥0.85；负例正确处理率 ≥0.99；原型“80% 命中”不能替代本条。
5. 身份/历史证据/持久性/越界等生产硬门槛与全部功能案例同时通过；性能与格式/平台也不能被质量总分豁免。

2 个百分点可作为研发改进目标，不替代严格胜出与置信门槛。不满足时继续诊断/修复：摄入/身份/解析/召回/排序/证据/推断/生成/维护分别定位，再用 dev 和消融验证。

## 7. 原始工件与反作弊

保留输入清单、gold、基线安装/健康检查、配置/提示、预算、原始逐题输出/工具轨迹、盲化裁决、耗时/token、失败与重试、源指纹、依赖和统计脚本。每条结果链接 raw 与 judgment 工件并校验 SHA-256。

复用索引/预处理只使用可见来源，每个系统同等机会，构建和人工整理成本另报；运行顺序随机/交错，清理会话、缓存与跨题记忆，知识复用题使用冻结的事件序列。禁用会泄漏 gold 的文件/网络入口。

baseline 运行错误若是环境配置造成，先修环境，不能把它当 domimap 优势。真正执行中的超时/错误保留并按统一政策重试；政策在看分数前冻结。

## 8. 当前工具与完成边界

本仓库新增评分/门槛工具用于验证已有比较包，**不负责自动安装四产品、采集真实业务任务或代替独立标注**。这些运行器/适配器是 M0/M2/M5 的显式工作，不能因评分器测试通过而勾选完成。

```bash
python3 -B benchmarks/evaluate.py --bundle out/benchmark/bundle.json
python3 -B benchmarks/evaluate.py --bundle out/benchmark/bundle.json --release
make release-check
```

synthetic 包只能 diagnostic_only，绝不成为正式 pass。缺基线/缺种子/坏工件/数据泄漏状态/样本不足/打平/CI 跨零均失败或不完整。真实工件结构也不能自动证明诚信与标注独立性；最终还需独立运行环境和可复核审查记录。
